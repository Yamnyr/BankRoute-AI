01 Corentin · Data Pipeline & Modélisation

Une mesure honnête, du Dummy à LoRA

  • banking77 — 13 069 requêtes réelles, 77 intentions, split 90/10 train/val + test held-out jamais touché avant l'évaluation finale.
  • Baseline Dummy (classe majoritaire) : 1.30 % — confirme un dataset ~équilibré, pas de triche possible.
  • Baseline TF-IDF + LogReg : 88.52 % — plafond purement lexical, en 3 secondes d'entraînement.
  • DistilBERT + LoRA (r=16, α=32, sur q_lin/v_lin) : 91.03 % accuracy pour seulement ~1.4 % des paramètres entraînés.

02 Quentin · Architecture logicielle

Un service typé, sécurisé, chargé une seule fois

Endpoints
GET/healthStatut & modèle chargé
GET/intents77 intentions × 7 départements
POST/predictRoutage unitaire + Top-3
POST/predict/batchLot, un seul forward pass
GET/docsSwagger UI interactif
  • Lifespan FastAPI : modèle + tokenizer chargés une fois au démarrage, préchauffés.
  • Pydantic strict : texte vide, espaces seuls, type corrompu, top_k hors limites → 422 systématique.
  • Enrichissement métier : le modèle ne sort qu'une intention — l'API la mappe vers son département (et sa description) via DEPARTMENT_MAPPING, sur les 77 intentions comme sur le Top-3.

04 Bilan

Ce qu'on revendique, ce qu'on ferait en plus

Bonus revendiqués
  • Routage hiérarchique 77 → 7 départements, mesuré (95.51 % de sauvetage)
  • Gestion 422 exhaustive, prouvée par tests négatifs
  • Benchmarking p50/p95 en conditions réelles
  • Conteneurisation Docker + healthcheck production-ready
Limites reconnues
  • Confusion résiduelle sur intentions sémantiquement proches (frontière département franchie dans ~4.5 % des cas)
  • Déterminisme GPU non forcé — variance de run à run de ±0.3-0.5 pt, assumée
  • Avec une semaine de plus : escalade humaine si confiance < 0.65, quantization ONNX/INT8, support multilingue, monitoring du data drift
